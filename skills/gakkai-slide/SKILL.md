# 学会・勉強会のスライドを作る

抄録・原稿・メモを受け取り、聞き手が迷わずに読める落ち着いたスライド（.pptx）を作る。飾りで目を引くのではなく、1枚に1つの結論を大きく、はっきり見せることを目指す。

このスキルに特定の組織のロゴ・配色・テンプレートは含まれていない。ロゴや色は依頼者が渡したものだけを使う。

## 1. 最初に確かめること

足りないものだけを短く聞く。わかっているものは聞き直さない。

| 項目 | 聞かれなかったときの既定 |
|---|---|
| 学会・勉強会の名前、発表の種類（口演・示説・勉強会） | 口演 |
| 持ち時間 | 学会の口演は7分、勉強会は20分 |
| 縦横比 | 16:9（学会の指定が4:3ならそれに合わせる） |
| 演者・共同演者・所属 | 原稿から読み取る。なければ空欄の印「◯◯」 |
| COI（利益相反）の有無 | 開示すべきものはない、として作り、要確認に挙げる |
| 基調色 | 紺（#1F4E9A）。依頼者の指定があればそれ |

## 2. 構成の型

### 学会（口演）
表紙 → COI開示 → 背景 → 目的 → 方法 → 結果（1〜3枚） → 考察 → 結論 →（文献）

- 枚数の目安は「持ち時間（分）× 1〜1.5枚」。7分なら8〜10枚
- 最後は「結論」で終わる。「ご清聴ありがとうございました」だけの1枚は作らない（質疑のあいだ、結論が映り続けるほうが伝わる）
- 倫理審査の承認（承認番号）は「方法」に書く

### 勉強会・院内研修
表紙 → 今日の結論（先に言う） → 本題（3つまで） → まとめ → 参考資料

## 3. 書き方の決まり

1. **タイトルは結論を1文で**。30字以内。「〜について」「結果」だけのタイトルにしない
   - ×「結果」 ○「記録時間は1人あたり平均80分から47分に減った」
2. **1枚に1つのメッセージ**。話題が2つあれば2枚に分ける
3. **本文は7行まで、24ポイント以上**。折り返しも1行に数える。入りきらなければ文を削るか分ける
4. **背景は白、装飾なし**。グラデーション・影・角丸の囲み・色の帯・絵文字・飾りのアイコン・写真の背景は使わない
5. **色は黒・グレーに基調色1色**。基調色は「いちばん見てほしい数字・棒・行」にだけ使う。赤と緑の違いで意味を伝えない（色の見え方の違う人にも伝わるように）
6. **グラフは見せたい1本だけに色**。ほかはグレー。数値は棒の上に直接書き、目盛りと補助線は省く
7. **表は3本線**（上・見出しの下・いちばん下の横線だけ）。縦線と塗りは使わない
8. **出典はそのスライドの下に**。図・表・グラフには必ずデータの由来を書く
9. **読み原稿はノートに書く**。1分300字を目安に、持ち時間に収める

## 4. 学会ならではの点検

作り終えたら、次を確かめて報告に入れる。直せないものは「要確認」にする。

- COI開示のスライドがある（学会の指定様式があればそれに従う）
- 個人が特定される情報がない（氏名・顔・ID・生年月日・入院日など）
- 抄録とスライドの数字が一致している
- 略語は初めて出るところで正式な名前を書いている
- 倫理審査の承認と番号を書いている（必要な研究のとき）
- 持ち時間に収まる（読み原稿の字数から見積もる）

## 5. 作り方

### 道具（scripts/build.mjs）が使えるとき
原稿を JSON にまとめ、`node scripts/build.mjs deck.json -o 出力.pptx` で作る。作ると同時に、上の決まり（タイトルの長さ・7行・COI・出典・絵文字・発表時間）を自動で点検し、気になった所を表示する。初回だけ `scripts` で `npm install` が必要。

JSON の形：

```json
{
  "meta": { "aspect": "16:9", "accent": "1F4E9A", "font": "BIZ UDPGothic",
            "footer": "第00回◯◯学会", "mode": "gakkai", "time_limit_min": 7 },
  "slides": [ { "type": "title", "title": "…", "notes": "読み原稿" } ]
}
```

スライドの型（`type`）：

| 型 | 使う場面 | 主な項目 |
|---|---|---|
| `title` | 表紙 | `event` `title` `subtitle` `authors` `affiliations` |
| `coi` | COI開示 | `presenter`、開示があるときは `items` |
| `bullets` | 背景・目的・考察など | `title` `lead` `items`（`{"text","sub":[]}` で下の段も可） `note` |
| `twocol` | 方法・比べるとき | `left` / `right` に `heading` `items`、強調したい側に `"accent": true` |
| `stat` | 大きな数字で見せる結果 | `items`（`label` `value` `detail` `accent`） `arrow` `note` |
| `chart` | 棒グラフ | `chart`（`categories` `values` `highlight` `unit` `suffix`） `note` |
| `table` | 3本線の表 | `columns` `rows` `colW` `highlightRow` `note` |
| `figure` | 図・写真 | `image`（JSONからの相対パス） `caption` |
| `conclusion` | 結論（3つまで） | `items` `thanks` |
| `references` | 文献 | `items` |

`chart` `table` `figure` には `source`（出典・データの由来）を付ける。どの型にも `notes`（読み原稿）を付けられる。

棒グラフは図形で描くため、PowerPoint・Keynote・Googleスライドのどれで開いても同じに見える。

### 道具が使えないとき
同じ寸法・同じ決まりで、使える方法（python-pptx など）で作る。寸法の目安（16:9、13.33×7.5インチ）：

- 左右の余白 0.7インチ。タイトルは上から0.4〜1.4インチ、30ポイント・太字、その下に細いグレーの線
- 本文は1.85インチから下、24ポイント。下の端0.5インチは出典とページ番号
- 文字は1種類のフォントだけ（既定は BIZ UDPゴシック。Mac で同じ見た目にしたいときは BIZ UDGothic）

## 6. 報告

作ったファイル、枚数、読み原稿から見積もった発表時間、点検で気になった所、要確認の一覧を短く伝える。数字・主張・出典は原稿のまま使い、勝手に変えない。
